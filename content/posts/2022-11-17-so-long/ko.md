**so_long**은 42에서 처음으로 창을 띄우는 과제입니다. 42가 만든 아주 작은 X11/Cocoa 래퍼인
[MiniLibX](https://github.com/42Paris/minilibx-linux)로 탑다운 게임을 만듭니다. 플레이어는 WASD로
움직이며 수집품을 모두 줍고 출구로 가야 하고, 이동 횟수는 터미널에 출력됩니다
([소스](https://github.com/PfClaKr/Ecole42Paris_Solong)).

게임 자체는 전체 작업의 3분의 1 정도입니다. 나머지는 주어진 맵이 플레이 가능한지 확인하는 일입니다.

## 맵 형식

맵은 `.ber` 텍스트 파일이고, 문자 하나가 타일 하나입니다.

```text
111111111111111111111111111111111111
11E000000010000111100C0000001100C011
1000010000100000101C010000C001010001
111000000000101000000000000001000001
1000010100100000101C000000C000000001
101001001010101000100100000001011111
1P00010000C1111000100000C11100000C11
111111111111111111111111111111111111
```

`1`은 벽, `0`은 바닥, `C`는 수집품, `E`는 출구, `P`는 플레이어입니다. 과제는 잘못된 맵의 조건을
나열하고, 프로그램은 각 경우에 `Error`를 출력하고 깔끔하게 종료해야 합니다.

- 맵이 직사각형이 아님
- 네 변이 모두 벽으로 닫혀 있지 않음
- `P`가 정확히 하나, `E`가 정확히 하나, `C`가 하나 이상이 아님
- 다른 문자가 섞여 있음
- **어떤 수집품이나 출구에 도달할 수 없음**

앞의 네 개는 격자를 도는 반복문이면 됩니다. 마지막은 탐색이 필요합니다.

## 맵을 깰 수 있는지 증명하기

검사는 플레이어 위치에서 시작하는 재귀 플러드 필입니다. 바닥과 수집품을 지나가며, 방문한 칸은
표시해서 다시 가지 않고, 벽과 출구는 막힌 칸으로 봅니다. 출구를 막힌 칸으로 보는 이유는, 제 게임에서는
전부 줍기 전에는 출구 위로 걸어갈 수 없기 때문입니다.

```c
int path_algo(t_map *m, char **map, int x, int y)
{
    if (x < 0 || y < 0 || x >= m->row || y >= m->col)
        return (0);
    if (x == m->c_row[i] && y == m->c_col[i])   // 현재 목표에 도착
        return (1);
    if (map[x][y] != 'P' && map[x][y] != '0' && map[x][y] != 'C')
        return (0);                              // 벽, 출구, 또는 이미 방문
    map[x][y] = '2';                             // 방문 표시
    return (path_algo(m, map, x + 1, y) || path_algo(m, map, x - 1, y)
         || path_algo(m, map, x, y + 1) || path_algo(m, map, x, y - 1));
}
```

플러드 필은 격자에 직접 쓰기 때문에 맵의 **복사본**에서 실행합니다. 제 버전은 목표마다(수집품 각각과
출구) 새 복사본을 만들어 탐색을 한 번씩 돌립니다. 맞긴 하지만 낭비입니다. `P`에서 한 번만 채운 뒤,
방문하지 않은 `C`가 남았는지, 방문한 칸 중 `E`에 닿은 칸이 있는지만 보면 한 번에 끝납니다. 지금이라면
그렇게 쓰겠습니다.

## 게임 루프

MiniLibX는 이벤트 기반입니다. 키 훅을 등록하고 `mlx_loop`에 제어를 넘깁니다.

```c
mlx_key_hook(win.win_ptr, key_input, &info);          // 키를 뗄 때
mlx_hook(win.win_ptr, 17, 0, win_exit, &win);          // 창 닫기 버튼
mlx_loop(win.mlx_ptr);
```

키를 누를 때마다 핸들러는 이동할 칸을 봅니다. 벽이면 아무 일도 없고, 바닥이면 플레이어가 움직이고,
수집품이면 움직이면서 카운터를 줄이고, 출구는 카운터가 0일 때만 게임을 끝냅니다. 그다음 32×32 XPM
스프라이트 다섯 개로 격자를 다시 그립니다.

## 배운 것

- **입력은 믿기 전에 검증합니다.** 코드도, 평가도 대부분 잘못된 맵에 관한 것입니다. 빈 파일, 빠진 개행,
  폭이 한 칸짜리인 맵.
- **모든 종료 경로에서 해제해야 합니다.** 창은 ESC, 빨간 X 버튼, 승리, 로딩 중 파싱 오류로 닫힐 수
  있고, 어느 경우든 맵과 이미지를 해제해야 합니다.
- **그래프 탐색은 뜻밖의 곳에서 나옵니다.** "게임" 과제가 제가 처음으로 DFS를 제대로 써 본 곳이었습니다.
