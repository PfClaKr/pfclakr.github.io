**Philosophers**는 다익스트라의 식사하는 철학자 문제를 42식으로 바꾼 과제입니다. 철학자 *N*명이 둥근
식탁에 앉아 있고, 두 사람 사이마다 포크가 하나 있습니다. 먹으려면 양옆의 포크 두 개가 모두 필요합니다.
먹고, 자고, 생각하고, 반복합니다. 누구든 `time_to_die` 밀리초 동안 식사를 시작하지 못하면 죽고
시뮬레이션이 멈춥니다([소스](https://github.com/PfClaKr/Ecole42Paris_Philosophers)).

```text
./philo 5 800 200 200 [7]
        │  │   │   │   └─ 선택: 모두 7번씩 먹으면 종료
        │  │   │   └─ time_to_sleep (ms)
        │  │   └─ time_to_eat (ms)
        │  └─ time_to_die (ms)
        └─ 철학자 수
```

출력은 `200 Philo 3 is eating` 같은 로그이고, 평가자는 이걸 꼼꼼히 봅니다. 죽은 뒤에는 어떤 메시지도
나오면 안 되고, 죽음은 10 ms 안에 출력되어야 합니다.

## 모델

철학자 한 명이 스레드 하나, 포크 하나가 `pthread_mutex_t` 하나입니다. 철학자 *i*는 포크 *i*와
*(i + 1) mod N*을 씁니다.

```c
info->philo[i].fork_left = i;
info->philo[i].fork_right = (i + 1) % info->num_philo;
```

먹는다는 건 두 뮤텍스를 잠그고, 식사 시각을 기록하고, `time_to_eat`만큼 기다린 뒤 푸는 것입니다.

## 교착 상태

모든 철학자가 동시에 오른쪽 포크를 집으면, 다들 포크 하나씩 든 채로 나머지 하나를 영원히 기다립니다.
고전적인 교착 상태이고, 순진하게 짜면 바로 일어납니다.

제 해결책은 **출발 시차**입니다. 짝수 번 철학자는 첫 식사 전에 `time_to_eat`만큼 기다립니다. 그러면
홀수 번이 먼저 포크 두 개를 잡고, 식탁이 번갈아 먹는 리듬으로 자리 잡습니다.

```c
if (philo->n % 2 == 0 && philo->info->num_philo != 1)
    usleep(1000 * philo->info->time_to_eat);
```

교과서적인, 더 견고한 해결책은 **잠금 순서**입니다. 항상 번호가 작은 포크를 먼저 잡습니다. 그러면
마지막 철학자가 첫 번째 철학자와 같은 포크를 노리게 되어 대기의 순환이 생길 수 없고, 스레드가 어떻게
스케줄되든 교착 상태가 불가능합니다. 시차는 실제로 동작하는 방법이고, 순서는 증명입니다.

철학자가 혼자면 포크도 하나뿐입니다. 하나를 집고, 두 번째는 영원히 못 잡으니 제시간에 죽어야 합니다.
코드에서는 특수한 경우로 처리합니다.

## 죽음 감시

철학자마다 두 번째 스레드인 모니터가 붙어서, 마지막 식사를 시작한 지 얼마나 지났는지 확인합니다.

```c
pthread_mutex_lock(&philo->philo_mutex);
if (get_time() - philo->start_time >= philo->info->time_to_die)
{
    print_philo(philo, 5);   // "died"
    philo->info->stop = 1;
}
pthread_mutex_unlock(&philo->philo_mutex);
usleep(100);
```

`start_time`은 철학자가 쓰고 모니터가 읽으니, 둘 다 `philo_mutex`를 거칩니다. 출력은 또 다른 뮤텍스를
거쳐서 두 줄이 섞이지 않게 하고, `stop`이 켜진 뒤에는 `print_philo`가 아무것도 출력하지 않습니다.

## 시간은 정확하지 않다

`usleep(200000)`은 *최소* 200 ms를 자고, 보통 몇 ms 더 잡니다. 긴 실행에서는 이 몇 ms가 쌓여서
죽지 않아야 할 철학자가 죽습니다. 해결책은 잘게 나눠 자면서 시계를 확인하는 것입니다.

```c
start = get_time();
while (get_time() - start <= time_to_sleep && !info->stop)
    usleep(1000);
```

이렇게 하면 자고 있는 철학자도 `stop`을 빨리 알아채서, 시뮬레이션이 끝난 뒤에 긴 낮잠을 마저 자는
일이 없습니다.

## 레이스 탐지기가 할 말

프로그램은 테스트에서 올바르게 동작하지만, `-fsanitize=thread`는 불평할 겁니다. 공유 플래그 `stop`은
모든 스레드가 잠금 없이 읽는 그냥 `int`이고, 식사 횟수는 다른 스레드가 올리는 동안 `check_meals`가
읽습니다. x86에서는 이 읽기가 우연히 동작하지만 데이터 레이스이고, C 표준은 아무것도 보장하지 않습니다.
지금이라면 `stop`을 출력 뮤텍스로 보호하거나 `atomic_int`로 만들고, 다 먹은 철학자 수를 잠금 아래에서
세겠습니다.

Philosophers의 진짜 교훈은 알고리즘이 아닙니다. 동시성 코드는 모든 테스트를 통과하고도 틀릴 수 있고,
도구(helgrind, ThreadSanitizer)는 손으로 하는 테스트가 못 보는 걸 본다는 것입니다.
