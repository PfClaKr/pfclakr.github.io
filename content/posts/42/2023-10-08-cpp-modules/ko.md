## 정통 캐노니컬 폼

모듈 02부터는 모든 클래스가 네 멤버를 선언해야 합니다. 기본 생성자, 복사 생성자, 복사 대입 연산자,
소멸자. C++98에서 컴파일러가 만들어 주는 버전은 포인터를 **얕게** 복사하기 때문에, 힙 메모리를 가진
클래스는 복사하는 순간 두 번 해제됩니다. 네 개를 직접 쓰다 보면 매번 자원을 복사한다는 게 무슨 뜻인지
정해야 합니다.

대입 연산자에는 따로 함정이 있습니다. `a = a`. `ref`에서 복사하기 전에 버퍼를 해제하는데 `ref`가 자기
자신이면, 복사할 원본을 방금 지운 셈입니다. 그래서 익숙한 이 검사가 들어갑니다.

```cpp
Fixed &Fixed::operator=(const Fixed &ref)
{
    if (this != &ref)
        this->raw = ref.getRawBits();
    return *this;
}
```

## 고정소수점 수

모듈 02에서는 `Fixed` 클래스를 만듭니다. 하위 8비트가 소수부인 `int`입니다. 변환은 시프트입니다.

```cpp
Fixed::Fixed(const int a)   : raw(a << frac) {}                    // 5   → 1280
Fixed::Fixed(const float a) : raw(roundf(a * (1 << frac))) {}      // 1.5 → 384
float Fixed::toFloat() const { return (float)raw / (1 << frac); }
```

덧셈은 그냥 정수 덧셈입니다. 곱셈은 배율도 같이 곱해지니 더 미묘합니다. 원시 값의 곱을 `(a * b) >> 8`로
되돌려야 합니다. 제 버전은 쉬운 길로 `toFloat()`을 거쳐 갔다가 돌아오는데, 맞긴 하지만 고정소수점을 쓰는
의미를 포기한 셈입니다. 연산자
오버로딩이 재주가 아니라 쓸모 있게 느껴지는 첫 순간입니다. `+ - * / < ==`와 `<<`를 정의하고 나면
`Fixed`가 내장 타입처럼 읽힙니다.

## 가상 소멸자

모듈 04에서 다형성의 함정을 만납니다. `Animal *`로 `Dog`를 delete할 때 `~Animal()`이 `virtual`이
아니면 `Animal` 부분만 소멸됩니다. `Dog`의 `Brain`은 조용히 샙니다. 규칙은 간단합니다. 가상 함수가
하나라도 있는 클래스라면 소멸자도 가상이어야 합니다.

같은 모듈에서 `Dog`를 `Brain`까지 **깊은 복사**하라고 합니다. 개를 복사했더니 두 마리가 뇌 하나를 나눠
쓰는 일이 없도록요. 캐노니컬 폼이 빛을 보는 순간입니다.

## 캐스트 하나 대신 넷

C에는 뭐든 하는 캐스트 하나뿐입니다. C++는 의도에 따라 나눕니다.

- `static_cast`: 컴파일러가 확인할 수 있는 변환 (`double`에서 `int`로, 확신이 있는 클래스 계층의
  업캐스트와 다운캐스트)
- `reinterpret_cast`: "이 비트를 다른 것으로 봐라". 모듈 06에서 포인터를 `uintptr_t`로 바꿨다가
  되돌릴 때 씁니다.
- `const_cast`: `const` 제거. 거의 항상 설계 문제의 신호입니다.
- `dynamic_cast`: 런타임 타입 정보로 **검사하는** 다운캐스트

모듈 06은 `typeid` 없이 `Base *` 뒤의 실제 타입을 알아내라고 합니다. 포인터에서는 실패한
`dynamic_cast`가 `NULL`을 돌려줍니다. 참조에는 널 참조가 없으니 대신 예외를 던집니다.

```cpp
void identify(Base &p)
{
    try { (void)dynamic_cast<A &>(p); std::cout << "A\n"; return; } catch (...) {}
    try { (void)dynamic_cast<B &>(p); std::cout << "B\n"; return; } catch (...) {}
    try { (void)dynamic_cast<C &>(p); std::cout << "C\n"; return; } catch (...) {}
}
```

## 모듈 09: 프로그램 세 개

마지막 모듈은 앞에서 배운 걸 모두 써먹는 연습 세 개로, 각각 다른 컨테이너를 써야 합니다(같은 컨테이너를
다시 쓸 수 없음).

**비트코인 환율 계산기** (`std::map`). 일별 가격 CSV와 `날짜 | 수량` 줄로 된 입력 파일이 주어지면,
수량마다 가치를 출력합니다. 날짜가 데이터베이스에 없으면 가장 가까운 **이전** 날짜를 씁니다. 정렬된 맵이면
호출 하나로 됩니다. `lower_bound(date)`는 그 날짜보다 앞서지 않는 첫 항목을 돌려주니, 한 칸 뒤로 가면
전날입니다.

**RPN** (`std::stack`). `"8 9 * 9 - 9 - 9 - 4 - 1 +"`을 계산합니다. 숫자는 쌓고, 연산자가 나오면 두
개를 꺼내 계산하고 결과를 다시 쌓습니다. 흥미로운 건 오류 처리입니다. 피연산자 부족, 0으로 나누기, 끝에
남은 값.

**PmergeMe**. **Ford-Johnson 병합 삽입** 알고리즘으로 수열을 정렬합니다. `std::vector`로 한 번,
`std::deque`로 한 번 해서 둘의 시간을 잽니다. Ford-Johnson이 최소화하는 건 시간이 아니라 *비교 횟수*입니다.

1. 원소를 둘씩 짝짓고 쌍마다 비교합니다. 큰 쪽들이 "메인 체인"이 됩니다.
2. 메인 체인을 재귀적으로 정렬합니다.
3. 작은 쪽들을 이진 탐색으로 끼워 넣는데, 순서는 **야콥스탈 수**(1, 3, 5, 11, 21, …)를 따릅니다. 그래야
   각 이진 탐색의 범위 크기가 2의 거듭제곱 바로 아래가 되어, 비교를 하나도 낭비하지 않습니다.

어려운 부분은 재귀 단계마다 전부 복사하지 않고 해내는 것입니다. 제 버전은 작은 `GroupIterator` 템플릿을
씁니다. 범위를 `size`개씩 묶은 *그룹*의 수열처럼 보이게 하고, 그룹은 마지막 원소로 비교합니다. "원소"
두 개를 바꾸면 그룹 전체가 바뀌니 재귀가 제자리에서 일어나고, 같은 코드가 두 컨테이너 모두에서 동작합니다.

```cpp
template <typename Iterator>
typename std::iterator_traits<Iterator>::reference
GroupIterator<Iterator>::operator*() const
{
    return this->iter[this->size - 1];   // 그룹은 마지막 원소로 대표됨
}
```
