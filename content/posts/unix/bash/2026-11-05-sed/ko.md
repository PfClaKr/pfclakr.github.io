sed 명령을 딱 하나만 아는 사람이 많습니다. `s/old/new/g`입니다. 이것만으로도 꽤 많은 일을 하지만,
sed는 사실 작은 프로그래밍 언어이고, "`[server]` 섹션 안의 `port`만 바꾸기"나 "백슬래시로 끝나는
줄 이어 붙이기" 같은 한 줄짜리를 가능하게 하는 건 나머지 기능들입니다. 이 글은 동작 모델부터
설명합니다. 모델이 이해되면 암호 같던 스크립트가 더 이상 암호가 아니게 됩니다.

모든 예제는 GNU sed 4.9로 실행했습니다. BSD/macOS sed와 다른 부분은 따로 표시했습니다.

## sed의 사고방식: 한 번에 한 줄

sed는 입력을 한 줄씩 **패턴 스페이스**(pattern space)라는 버퍼에 읽고, 스크립트 전체를 그 줄에
실행한 뒤, 패턴 스페이스를 출력하고 다음 줄로 넘어갑니다. 이게 루프의 전부입니다.

```bash
printf 'a\nb\nc\n' | sed 's/b/B/'
# a
# B
# c
```

매 사이클 끝의 자동 출력 때문에 `-n` 옵션이 있습니다. 자동 출력을 끄고, `p`로 직접 출력한 줄만
나오게 합니다.

```bash
printf 'a\nb\nc\n' | sed -n '2p'     # b
sed -n '5,10p' big.log              # 5~10번째 줄, head | tail과 같음
sed 3q file                         # 3줄 출력 후 종료: head -n 3
```

## 치환 제대로 쓰기

완전한 형태는 `s/정규식/치환문자열/플래그`입니다.

- **플래그**: `g`는 줄 안의 모든 일치를 바꾸고, 숫자는 N번째 일치만 바꾸고, `p`는 치환이
  일어났을 때 그 줄을 출력합니다(`-n`과 함께 유용). GNU에는 대소문자를 무시하는 `I`도 있습니다.
- **구분자는 아무거나**: `s` 바로 뒤의 문자가 구분자가 되므로 경로를 이스케이프할 필요가 없습니다.
- 치환 문자열의 `&`는 일치한 전체, `\1`…`\9`는 캡처 그룹입니다.
- `-E`는 확장 정규식(`+`, `?`, `()`, `|`를 백슬래시 없이)을 켭니다. GNU와 BSD 모두 지원합니다.

```bash
echo 'one one one' | sed 's/one/two/2'                 # one two one
echo 'PATH=/usr/local/bin' | sed 's#/usr/local#/opt#'  # PATH=/opt/bin
echo 'error 42' | sed -E 's/[0-9]+/[&]/'               # error [42]
echo 'Turing, Alan' | sed -E 's/^([^,]+), (.+)$/\2 \1/' # Alan Turing
```

GNU sed는 치환 문자열 안에서 대소문자 변환도 됩니다. `\U`는 `\E`까지 대문자로, `\L`은 소문자로,
`\u`/`\l`은 한 글자만 바꿉니다. 식별자 이름을 바꿀 때 편합니다.

```bash
echo 'max_retry_count' | sed -E 's/_([a-z])/\U\1/g'    # maxRetryCount (GNU 전용)
```

## 주소: 어느 줄에 적용할지 고르기

명령 앞에 **주소**(address)를 붙이면 그 명령이 실행될 줄을 고를 수 있습니다. 주소가 없으면 모든
줄에 실행됩니다.

| 주소 | 의미 |
|---|---|
| `3` | 3번째 줄 |
| `$` | 마지막 줄 |
| `/re/` | `re`와 일치하는 줄 |
| `10,20` | 10~20번째 줄 |
| `/BEGIN/,/END/` | `BEGIN`과 일치하는 줄부터 다음에 `END`와 일치하는 줄까지 |
| `/re/,+2` | 일치한 줄과 그 뒤 두 줄 (GNU) |
| `0~2` | 두 줄마다 하나: 시작~간격 (GNU) |
| `addr!` | `addr`와 일치하지 **않는** 모든 줄 |

설정 파일을 다룰 때 sed가 진짜 쓸모 있어지는 건 범위 덕분입니다. INI 파일의 `[server]` 섹션 안에
있는 `port`만 바꾸고 `[client]`는 그대로 두기:

```bash
cat config.ini
# [server]
# port=80
# [client]
# port=1

sed '/^\[server\]/,/^\[/ s/^port=.*/port=8080/' config.ini
# [server]
# port=8080
# [client]
# port=1
```

범위는 `[server]`에서 시작해서 다음에 `[`로 시작하는 줄에서 끝나므로, 치환은 그 사이 줄에만
적용됩니다. 몇 가지 더:

```bash
sed -e '/^[[:space:]]*#/d' -e '/^[[:space:]]*$/d' app.conf  # 주석과 빈 줄 제거
sed -n '/ERROR/,+2p' app.log                                # 에러마다 뒤 두 줄까지 함께
sed '/keep/!d' list.txt                                     # 일치하지 않는 줄 모두 삭제
seq 1 6 | sed -n '0~2p'                                     # 2 4 6
```

## s 말고 다른 명령들

| 명령 | 하는 일 |
|---|---|
| `d` | 패턴 스페이스를 지우고 다음 사이클로 |
| `p` | 패턴 스페이스 출력 |
| `q` | 출력(`-n`이 아니면)하고 종료 |
| `a text`, `i text`, `c text` | 줄 뒤에 추가, 앞에 삽입, 줄을 교체 |
| `y/abc/xyz/` | 문자 단위 변환, `tr`과 비슷 |
| `=` | 현재 줄 번호 출력 |
| `r file`, `w file` | 파일 내용을 출력에 끼워 넣기, 줄을 파일에 쓰기 |

```bash
sed '/^\[server\]/a timeout=30' config.ini   # [server] 다음 줄에 추가
printf 'a\nold\nb\n' | sed '/old/c\
new'                                         # 줄 전체 교체
sed -n '$=' file                             # 줄 수 세기, wc -l과 같음
```

한 줄로 쓰는 `a text` 형태는 GNU 확장입니다. POSIX(그리고 BSD)는 `a\` 다음 줄에 텍스트를 쓰는
형식을 요구합니다. macOS용 스크립트가 이상하게 생긴 이유가 이것입니다.

## 제자리 편집과 이식성 함정

`-i`는 결과를 표준 출력 대신 파일에 다시 씁니다. 문제는 GNU와 BSD의 문법이 다르다는 점입니다.

```bash
sed -i 's/foo/bar/' file        # GNU
sed -i '' 's/foo/bar/' file     # BSD / macOS: 백업 접미사가 필수, ''는 백업 없음
sed -i.bak 's/foo/bar/' file && rm file.bak   # 양쪽에서 모두 동작
```

`-i`에 대해 두 가지 더 알아 둘 것이 있습니다. 새 파일을 쓴 뒤 원래 파일 위로 이름을 바꾸는
방식이라 원본을 가리키던 하드 링크가 끊어집니다. 심볼릭 링크는 GNU의 `--follow-symlinks`를 주지
않으면 일반 파일로 바뀝니다. 그리고 일치하는 줄이 없어도 파일을 다시 쓰기 때문에 수정 시각이
바뀝니다.

## 홀드 스페이스: 여러 줄 다루기

sed에는 패턴 스페이스 말고 줄이 바뀌어도 유지되는 두 번째 버퍼, **홀드 스페이스**(hold space)가
있습니다. 둘 사이에서 데이터를 옮기는 명령은 다섯 개입니다.

| 명령 | 효과 |
|---|---|
| `h` / `H` | 패턴 스페이스를 홀드 스페이스로 복사 / 뒤에 추가 |
| `g` / `G` | 홀드 스페이스를 패턴 스페이스로 복사 / 뒤에 추가 |
| `x` | 둘을 맞바꿈 |

여기에 `N`(다음 입력 줄을 패턴 스페이스 뒤에 붙임), 레이블(`:a`), 분기(`b a`는 항상, `t a`는
치환이 성공했을 때만)를 더하면 여러 줄 작업 대부분을 할 수 있습니다.

**파일 뒤집기** (`tac`이 하는 일):

```bash
printf '1\n2\n3\n' | sed -n '1!G;h;$p'
# 3
# 2
# 1
```

줄마다 읽어 보면 이렇습니다. 첫 줄이 아니면 지금까지 모아 둔 것을 뒤에 붙이고(`G`), 결과를 다시
저장하고(`h`), 마지막 줄에서 출력합니다. 홀드 스페이스는 "현재 줄, 그 앞의 모든 줄" 순서로 커집니다.

**모든 줄을 쉼표로 합치기:**

```bash
printf 'a\nb\nc\n' | sed ':a;N;$!ba;s/\n/,/g'      # a,b,c
```

`N`이 계속 줄을 패턴 스페이스에 붙이고 `$!ba`가 마지막 줄까지 반복합니다. 그다음 치환 한 번으로
그 안의 줄바꿈을 바꿉니다. (`paste -sd, file`이 같은 일을 더 읽기 쉽게 합니다.)

**백슬래시로 끝나는 줄 이어 붙이기** (셸 스크립트나 Makefile처럼):

```bash
printf 'one \\\ntwo \\\nthree\nfour\n' | sed -e ':a' -e '/\\$/N; s/\\\n//; ta'
# one two three
# four
```

**일치하는 줄의 바로 앞 줄 출력:**

```bash
printf 'a\nb\nMATCH\nc\n' | sed -n '/MATCH/{x;p;x;}; h'    # b
```

모든 줄을 `h`로 저장해 두다가, 일치하는 줄이 나오면 맞바꿔서 이전 줄을 꺼내 출력하고 다시 맞바꿉니다.

## GNU와 BSD 한눈에 비교

| | GNU sed | BSD / macOS sed |
|---|---|---|
| 제자리 편집 | `-i` | `-i ''` |
| 치환 문자열의 `\n`, `\t` | 됨 | 안 됨 |
| `\U`, `\L` 대소문자 변환 | 됨 | 안 됨 |
| `시작~간격`, `addr,+N` | 됨 | 안 됨 |
| 한 줄짜리 `a text` | 됨 | 안 됨, `a\` + 줄바꿈 |
| `-E` | 됨 | 됨 |

macOS에서는 `brew install gnu-sed`로 `gsed`를 쓸 수 있습니다. 어디서나 돌아야 하는 스크립트라면
POSIX 범위 안에서만 쓰고, GNU에서 `sed --posix`로 확인해 보세요.

## sed를 쓰지 말아야 할 때

sed는 줄 단위로 동작하고 필드나 중첩 개념이 없습니다. "두 번째 열이 100보다 큰 줄의 세 번째 열"
같은 일이라면 awk가 맞습니다. JSON은 `jq`, 따옴표 안에 쉼표가 있는 CSV는 제대로 된 파서를 쓰세요.
여러 줄 스크립트에 `N`/`G` 트릭이 두세 개 넘게 필요하다면, 몇 줄짜리 awk나 Python이 6개월 뒤에
읽기 훨씬 쉽습니다.
